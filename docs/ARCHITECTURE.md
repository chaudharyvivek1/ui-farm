# Architecture

The repository is two things at once: the component library and the site that
documents it. This note explains how the two are connected.

## One source of truth

`components/ui/*.tsx` is the only place a component is written. Three artifacts are
derived from it:

1. **The live preview** — imported directly by `components/site/demos.tsx`.
2. **The TypeScript snippet** — the file is read from disk and highlighted at build
   time.
3. **The JavaScript snippet** — generated by `scripts/build-snippets.mjs`.

The Angular variants in `registry/angular/` are written by hand; they cannot be
generated from React, but they reuse the exact same Tailwind class strings so the
rendered result is identical.

## Snippet pipeline

```
components/ui/button.tsx
        │
        ├── esbuild transform (loader: tsx, jsx: preserve)  →  lib/generated/js/button.jsx
        │
        └── readFile + Shiki                                 →  highlighted HTML
```

`lib/snippets.ts` resolves the three variants for a slug:

| Variant | Source path | Shiki language |
| --- | --- | --- |
| React + TypeScript | `components/ui/<slug>.tsx` | `tsx` |
| React + JavaScript | `lib/generated/js/<slug>.jsx` | `jsx` |
| Angular | `registry/angular/<angularFile>` | `ts` |

Everything happens on the server at build time. The pages are static; the only client
JavaScript on a component page is the code tab switcher and the copy button.

## Highlighting

`lib/highlight.ts` creates one Shiki highlighter for the whole build and emits **both**
themes into the markup (`--shiki-light` and `--shiki-dark` CSS variables). Switching
theme is a CSS attribute change — no re-highlight, no hydration cost.

## Registry

`lib/registry.ts` is a typed array of `ComponentMeta`. It is the single input for:

- the sidebar groups (`getComponentsByCategory`)
- the component index page
- `generateStaticParams` for `/docs/components/[slug]`
- the props table, accessibility list and previous/next navigation

Adding a component to the library without adding it here means it will not be
reachable from the docs.

## Rendering model

- Pages under `app/docs/**` are Server Components.
- `components/site/demos.tsx` is a Client Component — it holds interactive demos.
- `components/site/code-tabs.tsx` is a Client Component — tab state and clipboard.
- `components/ui/**` is mostly framework-agnostic function components; the six
  interactive ones declare `'use client'` themselves.

## Styling

Tailwind v4 via `@tailwindcss/postcss`. The tokens are declared in `app/globals.css`
and exposed as utilities with `@theme inline`, but the components themselves use
arbitrary values (`bg-[var(--surface)]`) so they need no Tailwind configuration when
copied into another project.
